# دليل المغذيات — بنية التشغيل

هذه النسخة تعتمد على مبدأين:

1. أسماء المحطات والمغذيات المعروضة للمستخدم تُحفظ كما هي مكتوبة في الرسم، ولا يتم إنشاء أسماء بديلة.
2. يتم تحويل ملف `cad/FINAL DISPATCH - UPDATE.dwg` مرة واحدة إلى بيانات ثابتة داخل `data/feeders/`، ثم تقرأ صفحات الموقع JSON/SVG مباشرة. هذا يمنع الجوال من إعادة تحليل DWG في كل زيارة.

## بناء البيانات على GitHub

أضيف Workflow في `.github/workflows/build-feeder-data.yml`.
بعد رفع المشروع إلى GitHub، يمكن تشغيله يدويًا من Actions، كما يعمل تلقائيًا عند تغيير ملف DWG أو سكربت البناء.

الناتج:

- `manifest.json`
- `stations.json`
- `feeders.json`
- `all_text_entities.json`
- `all_objects.json`
- `layers.json`
- `blocks.json`
- `entity_types.json`
- `database_tables.json`
- `full_analysis.json`
- `raw_database.json`
- `drawing.svg`

إذا لم توجد البيانات الثابتة بعد، تستطيع صفحة `feeders.html` قراءة DWG مباشرة كخطة احتياطية.

## قاعدة الدقة

التعرف على `F.01` أو `F-01` هو مجرد ترشيح للعثور على النص، وليس إعادة تسمية. السجل يحتفظ بالنص الأصلي في `text/raw`.

إذا لم توجد قرينة هندسية كافية لربط مغذي باسم محطة، لا يتم اختراع اسم محطة؛ يبقى السجل غير محلول مع البيانات الخام المرشحة للمراجعة.
